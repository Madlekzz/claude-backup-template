# claude-backup

A daily, versioned backup of your Claude workspace in a GitHub repo: your organization's custom skills, Claude
Projects (instructions, knowledge docs and files) and Claude Design work. A local scheduled task in the Claude
desktop app runs every day, uses Claude in Chrome for the parts only claude.ai can export, and commits only what
changed.

> **Keep your copy private.** Once the first backup runs, this repo holds your Projects' instructions and
> uploaded files, your designs, and anything others shared with you. Create your repo from this template as
> **private**, and give access only to the people who should see all of it.

## What gets backed up

| Folder | Source | How |
|---|---|---|
| `skills/` | Skills your organization created (Anthropic's built-in skills are skipped) | `scripts/sync_skills.py` copies them from Claude Code's local org sync |
| `projects/<name>/` | Every Claude Project you can see: `instructions.md`, `attachments/`, `meta.json` | Claude in Chrome runs `scripts/export_projects.js`; `scripts/ingest_projects.py` files the export |
| `design/<name>/` | Design, Slides, Motion and Design System artifacts | The Artifact tool reads them; `scripts/ingest_artifact.py` files them |
| `design/<name>/` | Standalone claude.ai/design projects | Claude in Chrome downloads their zips; `scripts/ingest_design_zip.py` files them |

Items that disappear from Claude are never deleted here: they stay in the repo and show "removed in Claude
<date>" in the tables below. Every script compares content before writing, so a day with no real changes
produces no commit.

## Requirements

- A Claude plan with Claude Code, and the **Claude desktop app** (it runs the scheduled task).
- **Claude in Chrome**, with Chrome open and signed in to claude.ai when the task runs.
- `git` and `python3` (standard library only), and GitHub credentials on this computer that can push to your repo.
- For `skills/`: an organization (Team or Enterprise) whose skills Claude Code has synced at least once
  (`~/.claude/skills/synced/`). Without it, the skills section reports an error and the rest still runs.

## Setup

1. Click **Use this template → Create a new repository**, and choose **Private**.
2. Clone it, for example to `~/claude-backup`.
3. In the Claude desktop app, create a new scheduled task that runs **locally** (on this computer), with the
   clone as its folder and a daily time when your computer is usually on.
4. Paste the prompt from [`ROUTINE.md`](ROUTINE.md) as its instructions, replacing the folder and repo placeholders.
5. Run it once by hand and approve the actions it asks for. Later runs reuse those approvals.

The task only runs while the computer is awake and the desktop app is open. A missed day shows as skipped, and
the next run backs up everything that changed since the last push.

If your account belongs to several organizations, set `CLAUDE_ORG_UUID` for `sync_skills.py`, and tell the task
to set `window.__ORG` before running `export_projects.js`.

## Structure

```
claude-backup/
├── skills/            # one folder per skill, as synced from your organization
│   └── _manifest.json # sync metadata (name, description, last updated)
├── projects/<name>/   # instructions.md + attachments/ + meta.json
├── design/<name>/     # project/ (or db/ for Motion), assets/, meta.json
├── scripts/           # the daily sync; every write goes through these
├── ROUTINE.md         # the scheduled task prompt
└── README.md          # tables between BEGIN/END markers are generated by scripts/update_readme.py
```

`.work/` holds each run's temporary files and is gitignored.

## How to restore

### A skill into your organization (claude.ai)

1. Zip the skill folder so the folder itself is the root of the archive:
   ```sh
   cd skills && zip -r ../<skill-name>.zip <skill-name>
   ```
2. In claude.ai, upload the ZIP under your skills settings (org admins can publish it for the whole organization).
3. Check the skill shows up with the expected name and description, then test it in a new chat.

### A skill into Claude Code (local only)

```sh
cp -R skills/<skill-name> ~/.claude/skills/
```

Restart Claude Code; the skill becomes available as `/<skill-name>`.

### A Design artifact

1. Ask Claude (with the Artifact tool) to create a new artifact from the **Design** type.
2. Upload each file in `assets/` to the new artifact's asset store; each upload returns a new `/_blob/<id>` url.
3. Replace the old `/_blob/<id>` references in `project/` with the new urls (the mapping is in `meta.json`).
4. Publish the `project/` folder to the new artifact at the same paths.

Slides and Design System work the same way, created from the **Slides** / **Design System** type. For **Motion**,
create an artifact from the Motion type, upload `assets/`, update the `ref` in `db/assets/*.json`, then write each
`db/<collection>/<doc>.json` back with ArtifactData (`film/meta` first, `film/script` last, then the modules).

### A standalone claude.ai/design project

These are raw Claude Design project trees. Create a new Design artifact in Claude and publish the files under
`project/` at the same paths, or open the folder in Claude Code and ask Claude to rebuild it as a Design artifact.

### A Claude Project

1. In claude.ai, create a new Project with the name from `meta.json` (and its description, if any).
2. Paste `instructions.md` into the project's instructions.
3. Upload everything in `attachments/` to the project knowledge. Text docs come back as `.md`/`.txt` with the same content.
4. Re-share the project as needed (`is_private` in `meta.json` tells whether it was visible to the organization).

## Scripts

| Script | What it does |
|---|---|
| `scripts/sync_skills.py` | Copies new/changed org skills from `~/.claude/skills/synced/<org>/`; flags removed ones |
| `scripts/export_projects.js` | Runs in a claude.ai tab; downloads `claude-projects-export-<date>.json` |
| `scripts/ingest_projects.py <export.json>` | Writes changed/new projects; flags removed ones |
| `scripts/ingest_artifact.py ...` | Writes one changed/new Design/Slides/Motion/Design System artifact |
| `scripts/ingest_design_zip.py ...` | Writes changed/new standalone claude.ai/design projects from their zips |
| `scripts/mark_design_missing.py ...` | Flags design items no longer listed in Claude |
| `scripts/update_readme.py` | Regenerates the tables in this README |

## Limits

- The Projects export and the claude.ai/design steps rely on claude.ai pages and endpoints that are not a public
  API. If Anthropic changes them, those sections fail and the task reports it; the other sections keep running.
- Some project files have no downloadable original. They are listed in `meta.json` with a note instead.
- Skills are read from Claude Code's local org sync, so they are only as current as the last time Claude Code synced.
